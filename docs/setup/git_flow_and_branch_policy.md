# Git Flow 運用規約 ＆ ブランチ自動管理ガイド

本ドキュメントは、プロジェクトにおける **ブランチ運用ルール**、**コミットメッセージ規約**、および **GitHub / CI/CD / ローカル Git** を活用したブランチの自動クリーンアップ・管理仕様を定義します。

---

## 1. ブランチ戦略

### 主要ブランチ (Long-lived Branches)
- **`main`**: 安定したコードを保持する唯一の長期ブランチ。すべての作業ブランチは `main` から分岐し、PR で `main` へマージします。
- **`develop`**: 現在は**使用していません**。複数の機能を束ねてリリースする運用が必要になった時点で作成します。CIのトリガー（`branches: [main, develop]`）には、将来のために `develop` を残しています。

### サポートブランチ (Short-lived Branches)
作業ブランチは、`main` から `<接頭辞>/<内容>` の形式で作成します。`<内容>` は英数字とハイフンのみとします。

| 接頭辞    | 用途                                     | コミット種別         |
| :-------- | :--------------------------------------- | :------------------- |
| `feat/`   | 新機能の開発                             | `[feat]`             |
| `fix/`    | バグ修正                                 | `[fix]`              |
| `docs/`   | ドキュメントの更新                       | `[docs]`             |
| `test/`   | テストの追加・補完                       | `[test]`             |
| `chore/`  | ビルド・CI・不要ファイルの整理などの保守 | `[chore]`、`[other]` |
| `hotfix/` | 本番の急激な不具合修正                   | `[fix]`              |

マージ済みの作業ブランチは、ローカル・リモートとも削除します。

---

## 2. コミットメッセージ規約

コミットメッセージは `[種別] 概要` の形式とします。概要は日本語で記述します。

| 種別      | 用途         | 例                                 |
| :-------- | :----------- | :--------------------------------- |
| `[feat]`  | 新機能       | `[feat] ログイン画面追加`          |
| `[fix]`   | バグ修正     | `[fix] NULLチェック漏れの修正`     |
| `[docs]`  | ドキュメント | `[docs] 詳細設計書の追加`          |
| `[test]`  | テスト       | `[test] Phase 3の境界ケースを追加` |
| `[chore]` | 保守・整理   | `[chore] 不要なディレクトリを削除` |
| `[other]` | 上記以外     | `[other] .gitignore 更新`          |

論理的なまとまりごとにコミットを分けます。`main` へ直接 push せず、PR を経由します。

---

## 3. CI/CD ＆ リモート自動化 (GitHub / GitHub Actions)

不要なリモートブランチが残留しないよう、GitHub 標準機能で自動クリーンアップします。

### GitHub 設定: PRマージ後のリモートブランチ自動削除
- GitHubの管理画面 (`Settings` > `General` > `Pull Requests`) にて **`Automatically delete head branches`** を有効化。
- PRが `main`（または将来作成する `develop`）にマージされた時点で、リモートの作業ブランチが自動削除されます。

> 定期クリーンアップ用の GitHub Actions ワークフロー (`branch-cleanup.yml`) は廃止しました。
> コミット前の作成直後ブランチや、オープン中の PR の head ブランチを誤って削除するリスクがあったためです。

---

## 4. ローカル Git 開発環境の自動化設定

リモートで削除されたブランチがローカル環境に古い追跡情報 (`[gone]`) として残るのを防ぐため、以下の設定を推奨します。

### ① `git fetch` への自動 Prune 設定
以下のコマンドを実行すると、`git fetch` や `git pull` を行うたびに、リモートで消えたブランチのローカル追跡情報を自動的に削除します。

```bash
git config --global fetch.prune true
```

### ② ローカル `[gone]` ブランチを一括削除する Git エイリアス
追跡元リモートブランチが消えたローカルブランチを一括で整理・削除するコマンドを追加します。

```bash
# エイリアスの設定 (PowerShell / Git Bash 共通)
git config --global alias.cleanup "!git branch -vv | grep '\[gone\]' | awk '{print $1}' | xargs -r git branch -d"
```

#### 使い方
```bash
git cleanup
```
実行すると、リモートで既にマージ・削除されたローカルブランチが一括で安全に削除されます。
