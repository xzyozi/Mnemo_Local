# Local Semantic Memory 要求・機能仕様ドラフト

## 1. 目的

ローカルに保存したMarkdownメモと、利用者が明示的に読み込ませたブラウザ履歴・ブックマークを、外部サーバーへ送信せずに横断検索する。検索結果を時系列で集計し、利用者の興味関心の変化を確認できるようにする。

## 2. 対象範囲

- ローカルフォルダからのMarkdownファイル読込
- Chrome履歴・ブックマーク等のファイルのドラッグ＆ドロップ読込
- 入力データの正規化、ノイズURLの除外、形式検証
- Markdown見出しを基本単位としたチャンク化
- キーワード検索
- 意味検索（将来フェーズ）
- IndexedDBへの検索用データ保存（将来フェーズ）
- トピックのクラスタリングと月別推移表示（将来フェーズ）

## 3. 対象外範囲

- 外部サーバーへのデータ同期
- 利用者のブラウザ履歴を自動取得する拡張機能
- 複数利用者間の共有・認証
- サーバー側でのEmbedding生成
- 初回ドラフト時点での技術選定の確定

## 4. 機能要求

| ID      | 要求                                                                 | 受け入れ条件                                                                                             |
| :------ | :------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| REQ-001 | Markdownフォルダを選択して読み込める                                 | 利用者が選択したフォルダ内の`.md`を読み込み、タイトル・本文・パス・更新日時を保持できる                  |
| REQ-002 | 履歴・ブックマークをファイルから読み込める（Phase 2）                | 対応形式を定義し、履歴またはブックマークとして統一モデルへ変換できる                                     |
| REQ-003 | Markdownの不正・不要な入力を除外できる                               | 親参照・絶対パス、空本文を検索対象に登録しない。URL除外はPhase 2で定義する                               |
| REQ-004 | キーワードで検索できる                                               | 読み込み済みデータを対象に、タイトル・本文・Markdown相対パスから一致結果を表示できる                     |
| REQ-005 | Phase 1ではデータをメモリ上で扱い、Phase 2以降でローカルに保持できる | Phase 1はリロードでインデックスを再構築し、Phase 2では外部送信せずリロード後に検索用データを再利用できる |
| REQ-006 | 自然言語で関連データを検索できる                                     | 表現が一致しない関連チャンクも意味検索で取得できる（Phase 2）                                            |
| REQ-007 | 興味関心の推移を確認できる                                           | トピック別の月次件数または比率をグラフ表示できる（Phase 3）                                              |
| REQ-008 | トピック名を確認できる                                               | 各クラスタに頻出語または代表語から生成した表示名が付く（Phase 3）                                        |
| REQ-009 | 処理中もUIを操作できる                                               | 重いチャンク化・ベクトル化処理をWeb Workerへ分離する（Phase 2）                                          |

## 5. フェーズ分割

| フェーズ | 範囲                                     | 完了条件                                                |
| :------- | :--------------------------------------- | :------------------------------------------------------ |
| Phase 1  | 読込、正規化、全文検索                   | Markdownを読み込み、ブラウザ上でキーワード検索できる    |
| Phase 2  | Worker、Embedding、IndexedDB             | 自然言語検索ができ、リロード後にEmbeddingを再計算しない |
| Phase 3  | クラスタリング、トピック命名、推移グラフ | 数ヶ月から数年の関心領域の変化をグラフで確認できる      |

## 6. 未決事項

- Phase 1の全文検索方式（日本語n-gramの実装方法と検索対象件数上限）。
- 初回配布方式を「CDNからES Modulesを読み込む単一HTML」と「Bunで生成する単一JS」のどちらにするか。
- 対応する履歴・ブックマークの入力形式と上限サイズ。
- Embeddingモデル、モデルファイルの取得元、初回ダウンロードの扱い。
- IndexedDBのスキーマバージョンと削除・再構築UI。
- トピック命名とクラスタリングの品質評価方法。
