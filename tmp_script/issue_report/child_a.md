親 Issue: #30

## 背景
コミット形式(`[種別] 概要`)、Issue 起点の運用、秘密情報ファイルの混入防止は、現在レビューの目視に頼っている。
言語非依存で軽い検査として、1つのワークフローにまとめて自動化する。

## 対応内容
新規ワークフロー `.github/workflows/pr-guard.yml`(`pull_request` で実行、1ジョブにまとめる)。

| 検査 | 内容 |
| :-- | :-- |
| コミットメッセージ形式 | PR 内の非マージコミットが `[種別] 概要` に一致するか。種別は `.gemini/git.md` の一覧(feat / fix / update / refactor / remake / style / clean / delete / test / core / docs / WIP / other) |
| 禁止ファイル混入 | `.env*`、`*.pem`、`*.key`、大容量ファイル(目安 1MB 超)が PR の追加ファイルに含まれていないか |
| Issue 紐付け | PR 本文に `Closes` または `Refs` + `#番号` があるか |

## 設計上の注意
- シェルと git のみ。追加ツールなし。
- 当面は警告(`::warning::`)で運用し、誤検知が無いことを確認してから失敗に引き上げる。
- Dependabot 等のボット PR は、コミット形式の検査対象外にする(または Dependabot 側の設定で接頭辞を付ける)。
- 検査の判定は PR 本文・コミット・差分のみ。秘密情報の内容検査(gitleaks 等)は #14 で扱う。

## 受け入れ条件
- [ ] 規約に合わないコミット、禁止ファイル、Issue 紐付けなしの PR で、それぞれ警告が出る。
- [ ] 規約どおりの PR で警告が出ない。
- [ ] ジョブ全体の検査部分が約1秒以内に終わる。
- [ ] 検査内容と運用を `docs/setup/` の文書に記載する(`repo_hygiene.md` への追記でもよい)。
