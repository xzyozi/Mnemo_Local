### 調査で分かった前提
- 現行の `validate_docs.py` は、`related_documents` の相対パス実在だけを検査している。本文リンクは未検査。
- 形式文書の命名規約は `[PROJECT_PREFIX]-[TYPE_CODE]-[NUMBER]_[TITLE].md`。ADR は `ADR-001_<TITLE>.md` が基本で、既存の `001-document-governance-and-ssot.md` は移行まで維持するとされている。
- `PROJECT_PREFIX` は派生プロジェクトごとに決まるため、検査側では固定できない。

### Q1 検査するリンクの種類
インライン `[text](path)`、画像 `![alt](path)`、参照形式 `[id]: path`、HTML `<a href>` のどこまでか。
- **推奨**: インライン、画像、参照形式。HTML は対象外(このリポジトリの文書では使われていない)。

### Q2 アンカー(`#見出し`)の検証
- **推奨**: 初版はファイルの実在のみ。アンカーは、見出しから ID を作る規則(特に日本語)が複雑なため、別 Issue に分ける。

### Q3 検査から除外する範囲
- **推奨**: コードフェンス内(`mermaid` を含む)とインラインコード内は対象外。外部 URL(`http(s)://`、`mailto:`)も対象外。

### Q4 絶対パスと `file:///`
`docs/design/TEMPLATE/README.md` §6① は、ローカル絶対パスの埋め込みを禁止している。
- **推奨**: `file:///` と Windows ドライブ文字(`C:\`)のリンクも、本検査で警告に含める。規約の機械化として小さく足せる。

### Q5 TEMPLATE 内のプレースホルダリンク
- **推奨**: `related_documents` の検査と同じ規則で、`...` や `[` を含むリンクはスキップする。

### Q6 警告とエラーの区分
リンク切れ、番号不一致をどちらにするか。
- **推奨**: リンク切れは、まず警告で現行 docs のベースラインが0件であることを確認し、その後エラーに引き上げる。ADR 番号の重複は、明確な欠陥なので最初からエラー。文書番号とファイル名の不一致は警告。

### Q7 文書番号とファイル名の一致
- **推奨**: ファイル名が `document_number` で始まるかだけを検査する(`PROJECT_PREFIX` 部分は番号側にすでに含まれるため、固定の接頭辞は要らない)。ADR の既存命名(`001-…`)は、除外リストに明示する。

### Q8 ADR の既存ファイル名の移行
- **推奨**: 移行しない(改名はリンクと履歴に影響する)。除外理由をスクリプトのコメントと文書に書き、新規 ADR から新形式を適用する。

### Q9 番号重複の検査範囲
ADR のみか、全形式文書(BD/DD/DS/IF/ENV)か。
- **推奨**: 全形式文書で、`document_number` の一意性を検査する(TEMPLATE を除く)。ADR だけに限定するより一般的で、実装も同程度。

### Q10 性能
- **推奨**: 差分ではなく全件を検査する。現状約0.3秒で、数百ファイルでも1秒以内に収まる見込み。超えた時点で見直す。
